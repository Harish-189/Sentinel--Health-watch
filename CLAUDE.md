# CLAUDE.md: Sentinel

Public-health early-warning system (hackathon). Full requirements live in `SPEC.md`: read the relevant section only, not the whole file, unless asked.

## Stack
- Backend: Python 3.11, FastAPI, pydantic v2, SQLite (SQLAlchemy), numpy/pandas/scipy/statsmodels
- LLM: Anthropic SDK; model names come from env (`ANTHROPIC_MODEL`, `ANTHROPIC_MODEL_FAST`); never hardcode keys
- Frontend: React + Vite + TypeScript, Tailwind, Apache ECharts, TanStack Query
- Tests: pytest (backend), Vitest + Playwright (frontend)
- Infra: Docker, docker-compose, GitHub Actions

## Commands
- Backend dev: `cd backend && uvicorn app.main:app --reload`
- Backend tests: `cd backend && pytest -q`
- Lint/types: `ruff check . && mypy app`
- Frontend dev: `cd frontend && npm run dev`
- Frontend tests: `cd frontend && npm test`
- Eval harness: `cd backend && python -m app.eval.harness --runs 200`
- Full stack: `docker compose up --build`

## Layout
`backend/app/{data,detection,analysis,agents,governance,eval}`, `backend/tests`, `frontend/src`, `docs/`. Thresholds live in `backend/config.yaml`, not in code.

## Non-negotiable rules
1. **Aggregate data only.** Never add a person-level field, table, or column. PII-like column names are rejected at ingestion.
2. **The LLM never decides evidence tiers.** Tiering is deterministic code in `analysis/evidence.py`. The LLM explains and proposes only.
3. **Every LLM claim cites evidence IDs** and must pass `agents/verifier.py`. Ungrounded claims are dropped.
4. **No action executes without human approval.** All actions go through `governance/approvals.py` and write to the audit log.
5. **No individual diagnosis or personalized prediction.** Keep the guardrail test passing.
6. **Every forecast shows uncertainty bands.**
7. **The offline fallback must keep working** when the LLM is unavailable (`LLM_MODE=offline`).

## Working style (saves tokens)
- Work one SPEC phase at a time; stop and report after each. Do not start the next phase unprompted.
- Use Plan mode before any change touching more than 3 files.
- Read files by exact path; do not scan the repo broadly. Use subagents for exploration and review.
- Never send raw time series to the LLM: send compact evidence JSON.
- Write the test first for detectors, evidence gate, privacy, and guardrails.
- Run `pytest -q` and `ruff check .` after changes; fix failures before reporting done.
- Keep functions small and typed. No new dependency without saying why.
- Commit after each green phase with a conventional message (`feat:`, `test:`, `fix:`).

## Do not
- Edit `backend/data/generated/` (regenerated by the simulator).
- Commit `.env` or any key.
- Use real health data or real place names.
- Add UI libraries beyond Tailwind + ECharts without asking.

## Frontend style
Dark mission-control theme; design tokens in `frontend/src/theme.ts`. Tier colors: E0 gray, E1 blue, E2 amber, E3 red. Use the `frontend-design` skill for new pages.
